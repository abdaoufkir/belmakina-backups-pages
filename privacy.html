Privacy Policy

This policy describes how BeLmakina Backups, an internal backup utility for the BeLmakina POS system, uses authorization to the operator's Google Drive account.

Purpose and information processed

The application creates and manages recovery copies of the POS database and product-image storage. The application may process the Google Drive account authorization needed to create files, Google Drive file IDs and associated metadata, and the backup files it uploads. Backup content may contain internal business records and product-image data from the POS system.

Google Drive permissions

The application requests https://www.googleapis.com/auth/drive.file, which permits it to access and manage the specific Drive files and folders created or opened with this application. It does not request the broader permission to access the entire Google Drive account.

How information is used and stored

Information is used solely to prepare, transmit, store, validate, and, when required, recover operational backup files. Backup payloads are encrypted before upload. Some archive names and container metadata may remain visible as metadata in Google Drive.

Authorization tokens may be stored in the operator's local rclone configuration and, once automation is enabled, in a protected GitHub Actions secret used by the backup workflow. Backup files are stored in the operator's Google Drive account. Google and GitHub provide the relevant hosting and automation infrastructure.

Sharing and selling data

The application does not sell Google user data, use it for advertising, or intentionally share backup content with unrelated third parties. Data is processed by the services necessary to run the workflow, including Google Drive and GitHub Actions.

Retention, deletion and access withdrawal

Backup files remain in the operator's Google Drive until the operator deletes them or applies a retention policy. The operator can delete the backup files and revoke the application's access from their Google Account security settings. Revoking access stops future authorized access but does not automatically delete backup files already stored in Drive.

Security

Backups are prepared for encrypted storage and access is limited using Google OAuth's drive.file scope. The operator is responsible for protecting the encryption recovery key, OAuth credentials, and access to the Drive and GitHub accounts.

Contact

For privacy or access questions, contact the operator using the support email listed on the BeLmakina Backups Google OAuth consent screen.
